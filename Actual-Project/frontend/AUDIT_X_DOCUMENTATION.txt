A1. PROJECT OVERVIEW (কী তৈরি হচ্ছে)
────────────────────────────────────────────────────────────────────────────────────────────────────

  AUDIT-X হলো একটি Professional Financial Auditing Platform।

  এই প্ল্যাটফর্মে একটি Audit firm-এর:
  → Student/Audit Staff (যারা financial statements তৈরি করে)
  → Manager/Admin (যারা review করে, approve করে)
  → Partner/Super Admin (যারা পুরো সিস্টেম manage করে)

  এই তিনটি role নিয়ে কাজ করা হয়।

  কী ধরনের কাজ হয়:
  ──────────────────
  1. Audit firm একটি client company-র financial statements তৈরি করে
  2. Company create করো, Financial Year create করো
  3. Financial Statements fill করো:
     → Cover Page (Report cover)
     → SFP (Statement of Financial Position — Balance Sheet)
     → PNL (Profit & Loss Statement)
     → SCE (Statement of Changes in Equity)
     → SCF (Statement of Cash Flows)
     → PPE Schedule (Property, Plant & Equipment — Annexure A)
     → N4-13 (Notes 4 থেকে 30 পর্যন্ত)
     → P_Discussion (First Discussion Meeting Paper — 13 pages)
  4. সব ঠিক হলে Submit করো review-এর জন্য
  5. Manager review করে, changes চাইলে student আবার edit করে
  6. Final হলে Finalize করে Lock করা হয়
  7. এই সব প্রক্রিয়ায় Notifications যায় relevant users-এ

  বর্তমান prototype এই সব কাজ করতে পারে — কিন্তু শুধু localStorage-এ।
  আমাদের কাজ হলো এটাকে real backend + database দিয়ে production-ready করা।

A6. REVIEW WORKFLOW (রিভিউ ফ্লো — Business Logic)
────────────────────────────────────────────────────────────────────────────────────────────────────

  FinancialYear এর reviewStatus Flow:

  DRAFT ──────────────────────── [Student: Submit] ──→ SUBMITTED
    ↑                                                       ↓
    │                                              [Admin: Start Review]
    │                                                       ↓
    │                                               UNDER_REVIEW
    │                                              ↙           ↘
    │                              [Admin: Request Changes] [Admin: Finalize]
    │                                     ↓                       ↓
    │                           CHANGES_REQUESTED              FINALIZED
    └──── [Student re-edits → re-submits] ←┘               (isLocked = true)
                                                                   ↓
                                                           [Admin: Reopen]
                                                                   ↓
                                                              DRAFT again
                                                           (isLocked = false)

  State Details:
  ─────────────
  DRAFT           → student এবং admin edit করতে পারে। isLocked = false
  SUBMITTED       → student আর edit করতে পারে না (locked for editing by student)
  UNDER_REVIEW    → admin reviewing. No edits allowed
  CHANGES_REQUESTED → student আবার edit করতে পারে এবং re-submit করতে পারে
  FINALIZED       → সব locked. isLocked = true. শুধু admin Reopen করতে পারে

  Notification Triggers:  ─────────
  src/services/httpClient.ts            → Axios instance + interceptors
  src/services/auth.service.ts          → login, register, logout, me
  src/services/company.service.ts       → company CRUD
  src/services/financialYear.service.ts → year CRUD + rollover
  src/services/financialData.service.ts → audit/notes/discussion data
  src/services/review.service.ts        → submit, review, finalize
  src/services/notification.service.ts  → notifications
  src/services/user.service.ts          → user management

B4. ARCHITECTURE PATTERN (Data Flow)
────────────────────────────────────────────────────────────────────────────────────────────────────

  Request Flow:
  ─────────────
  Browser (React) → Better Auth Client (auth APIs) → Express Server → Better Auth Handler
  Browser (React) → httpClient.ts (Axios) → Express Server → Prisma → PostgreSQL

  Auth Flow (Session-Based via Better Auth):
  ──────────────────────────────────────────
  Login → Better Auth creates session in DB → Sets `better-auth.session_token` cookie
  All requests → Browser sends session cookie automatically
  Session expired → Better Auth returns 401 → Frontend redirects to /auth
  ⚠️ NO refresh token flow — Better Auth handles session renewal automatically
  ⚠️ NO manual JWT verification — `auth.api.getSession()` does everything

  Financial Data Flow:
  ─────────────────────
  User edits note → Zustand store updates (instant UI) → 2s debounce
  → financialDataService.updateNotesData() → API PATCH → Database saves

  Server-Side Pattern:
  ─────────────────────
  Auth routes: /api/auth/* → Better Auth handler (toNodeHandler)
  App routes:  Route → Auth Middleware (auth.api.getSession) → Role Middleware (check role)
  → Validation Middleware (Zod schema) → Controller → Service → Prisma → Response

F2. AUTH FLOW (Better Auth Session Based)
────────────────────────────────────────────────────────────────────────────────────────────────────

  Login Flow:
  ──────────
  Step 1: User enters email + password
  Step 2: Better Auth client calls signIn()
  Step 3: Better Auth sets session token cookie automatically.
  Step 4: Frontend updates Zustand store / relies on useSession() from Better Auth.

  Session Flow:
  ─────────────
  Step 1: session is handled seamlessly by Better Auth.
  Step 2: Server automatically resolves sessions on /auth/me or middleware.
  Step 3: If 401 Unauthorized occurs, redirect to login.

  Page Reload Auth Check:
  ─────────────────────────
  Step 1: App mounts
  Step 2: DashboardLayout calls GET /auth/me on mount
  Step 3: If success → set user in Zustand
  Step 4: If 401 → redirect to /auth

  ⚠️ Frontend কখনো token নিজে localStorage-এ রাখবে না।
  ⚠️ Cookies httpOnly — JavaScript access নেই, XSS safe।
  ⚠️ withCredentials: true ছাড়া cookies যাবে না।

    // 5. Fetch user from DB: await prisma.user.findUnique({ where: { id: decoded.id } })
    // 6. Check: user exists, not deleted, not DELETED status
    // 7. Attach to req: req.user = { id, email, role, status }
    // 8. Call next()
  }

  ── role.middleware.ts ──
  export const authorize = (...allowedRoles: UserRole[]) => {
    return (req, res, next) => {
      if (!req.user) → ApiError(401)
      if (!allowedRoles.includes(req.user.role)) → ApiError(403, "Insufficient permissions")
      next()
    }
  }
  // Usage: router.get('/users', authenticate, authorize('ADMIN', 'SUPER_ADMIN'), controller.getUsers)

  ── validate.middleware.ts ──
  export const validate = (schema: ZodSchema) => {
    return (req, res, next) => {
      const result = schema.safeParse(req.body)
      if (!result.success) {
        const errors = result.error.errors.map(e => ({ field: e.path.join('.'), message: e.message }))
        → ApiError(400, "Validation failed", errors)
      }
      req.body = result.data  // Use sanitized data
      next()
    }
  }

  ── error.middleware.ts ──
  export const globalErrorHandler = (err, req, res, next) => {
    if (err instanceof ApiError) {
      return res.status(err.statusCode).json({
        success: false,
        message: err.message,
        errorDetails: err.errorDetails || undefined
      })
    }
    // Unknown errors
    return res.status(500).json({
      success: false,
      message: NODE_ENV === 'production' ? 'Internal server error' : err.message
    })
  }
